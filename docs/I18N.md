# Internationalization

The UI is localized with [Project Fluent](https://projectfluent.org). English
is the source catalogue. Every shipped language has a complete catalogue: a
missing key is a test failure, not a partial language.

review. `i18n-check` and the test suite validate structure, placeholders,
plural categories and formatting, not literary quality.

## Layout

```
crates/i18n/
  src/lib.rs              translator, negotiation, bundle cache, date/number formatting
  src/bin/i18n-check.rs   catalogue status for translators and reviews
  locales/en/common.ftl   source catalogue
  locales/fr/common.ftl   French catalogue
crates/ui/src/locale.rs   use_i18n, language preference, document lang/dir
crates/host/src/html.rs   public Host pages and Accept-Language negotiation
```

- Catalogues are embedded with `include_str!`; there are no runtime files to
  install on desktop, web or Android.
- `jabu-i18n` has no Dioxus dependency. Parsed Fluent bundles are cached per
  thread; `Translator` is a small `Copy` value holding the resolved tag, so it
  can be passed into closures and spawned tasks.
- Locale detection uses `sys-locale` (Linux, Windows, macOS, Android, wasm).
  The chain is exact tag → base language → English.
- `ui.language` stores `system` or a BCP-47 tag. The resolved tag lives in
  `ClientState.language` and drives `<html lang>` and `dir`.

## Using strings

Inside a component:

```rust
let i18n = locale::use_i18n();
rsx! {
    h2 { "{i18n.t(\"settings-title\")}" }
    input { placeholder: i18n.t("chat-search-placeholder"), .. }
    span { "{i18n.tn(\"chat-unread\", unread as i64)}" }
}
```

- `use_i18n()` reads the language signal, so the component re-renders when the
  language changes. Call it once at the top of the component.
- Keys use lowercase words separated by hyphens (`nav-chats`,
  `chat-send-placeholder`, `time-minutes-ago`). Fluent does not allow dots.
- Use full messages with `$placeholders`; never concatenate translated
  fragments.
- Pure helpers take `&jabu_i18n::Translator` (see `format_time`) or return keys
  that the component translates.
- Do not translate protocol identifiers, JIDs, stanza data, logs, file names
  or user content. Raw backend error detail stays as-is; translate the label
  around it.

## Dates and numbers

`Translator` formats dates and numbers so components never call
`strftime`-style APIs directly:

```rust
i18n.date(timestamp);          // Nov 10, 2026 / 10 nov. 2026
i18n.clock(timestamp);         // 14:05
i18n.date_time(timestamp);     // Nov 10, 2026, 14:05 / 10 nov. 2026 à 14:05
i18n.number(1_234_567);        // 1,234,567 / 1 234 567
i18n.decimal(1234.5, 1);       // 1,234.5 / 1 234,5
```

Month names and the date/date-time patterns are catalogue keys
(`date-month-*`, `date-medium`, `date-time`, `time-hm`). Grouping and decimal
separators are locale data in `number_separators`, because they are
punctuation rather than prose. Add a new language branch there when the
separators differ.

## Counted messages

Use Fluent selectors:

```ftl
chat-unread =
    { $count ->
        [one] { $count } unread message
       *[other] { $count } unread messages
    }
```

French plural categories differ: `0` and `1` use `one`, `2+` use `other`.
Test both languages when adding a counted message.

## Adding a message

1. Add the key to `locales/en/common.ftl` with the English source.
2. Add the same key to every shipped catalogue (`fr` today).
3. Use it through `i18n.t`, `i18n.tn` or `i18n.t_args`.
4. Run `cargo test -p jabu-i18n -p ui --lib`. The tests reject duplicate IDs,
   mismatched key sets and UI keys that are missing from English.

## Contributing a translation

Start from the English template and work in a fork:

```sh
cargo run -p jabu-i18n --bin i18n-check -- --template de \
  > crates/i18n/locales/de/common.ftl
```

Translate every value, keep the message ids, `$placeholders` and plural
selectors unchanged, and do not copy another project's catalogue. Then follow
"Adding a locale" below. A fluent speaker should review the result; the
project has no formal review queue yet, so a pull request with the catalogue
and the `i18n-check` output is the current workflow.

## Adding a locale

1. Create `locales/<tag>/common.ftl` with every English key translated. The
   `--template` command above produces the starting file.
2. Add an `include_str!` constant and a `resources` arm in `crates/i18n/src/lib.rs`.
3. Add a `LanguageInfo` entry to `SUPPORTED` (the endonym, not an English name).
4. Run `cargo run -p jabu-i18n --bin i18n-check`; it must report zero missing
   and zero extra keys.
5. Run the catalogue tests and the UI in that language. For an RTL language,
   also audit physical direction classes; see the RTL note below.

## Host pages

`crates/host` renders public pages on the server. Each request negotiates
`Accept-Language` against the shipped catalogues, the layout emits matching
`lang` and `dir` attributes, and responses set `Vary: accept-language`.
Public blog, post, contact, report, community, Space, Story and not-found
pages are translated. The operator-facing admin pages (queue, settings and
tokens) use the same negotiation and translator, including form validation
messages.

## Clean-room rule

Movim is AGPL. Do **not** copy its translation catalogues, wording, templates
or assets. Jabu's catalogues are original contributions under the project's
MIT licence. When a term matches Movim exactly by coincidence that is fine;
copying whole files is not.

## Testing

- `cargo run -p jabu-i18n --bin i18n-check`: prints key counts and lists
  missing or extra keys for every catalogue.
- `cargo test -p jabu-i18n --lib`: catalogue parity, plurals, fallback,
  negotiation, date/number formatting, RTL detection.
- `cargo test -p ui --lib`: every key used in `ui`/`app` exists in English.
- `cargo test -p host --lib`: public pages render in French and
  `Accept-Language` negotiation follows header order.
- Headless run: `JABU_LANG=fr target/.../jabu …` (debug builds) and check the
  debug log `document language: fr (ltr)`.
- RTL layout: `JABU_DIR=rtl` (debug builds) forces `dir="rtl"` without shipping
  an RTL catalogue; the log then reports `document language: en (rtl)`. A UI
  test rejects new physical `ml-*`/`mr-*`/`text-left`/`text-right` classes.
- Manual: switch language in Settings, restart, and verify the choice
  persists and the interface updates without reconnecting accounts.

## Known gaps

- The Host admin pages are localized, but the admin console is still served as
  plain HTML; there is no in-page language switcher (visitors rely on the
  browser's `Accept-Language`).
- Android has no localizable app strings yet. The launcher label is the Jabu
  brand supplied by the generated Gradle project, and mobile notifications and
  channels are still a stub. When channels are added, their names must come
  through the translator. Notification text the app produces today is
  translated.
- Arabic ships and drives the RTL layout on desktop and Host pages. Hebrew is
  not shipped. Icons, bidi runs around Latin JIDs and native review of the
  Arabic wording are still open.
- Dates use 24-hour time. English and French use abbreviated months, the newer
  catalogues use full month names; weekdays, time-zone names and locale digit
  shaping are not implemented.
- Catalogues are machine-assisted and have no native review yet. `i18n-check`
  validates key parity, placeholders and plural categories, but a fluent
  speaker should still review wording before calling a translation final.
- The high-confidence language list is complete. Traditional Chinese and
  European Portuguese are possible future catalogues; native review remains
  the main open item.
